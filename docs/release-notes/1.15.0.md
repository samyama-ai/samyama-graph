# Release Notes — v1.15.0

**Unreleased.** Entries are added as changes merge; the date, the commit count
and the summary are written with the version bump.

## Read this before upgrading

- **`db.index.vector.queryNodes` yields `score` as a similarity, higher is
  better (#1980).** It used to be the raw distance, lower is better: the nearest
  neighbour of a query scored about 0. Neo4j's `score` is a similarity in [0, 1],
  so a query ported from Neo4j with `ORDER BY score DESC` or `WHERE score > 0.9`
  returned the worst matches. `score` now follows Neo4j:

  | index metric | `distance` (the old `score`) | `score` |
  |---|---|---|
  | `cosine` | `1 - cos` | `(1 + cos) / 2`, in [0, 1] |
  | `l2` / `euclidean` | Euclidean distance `d` | `1 / (1 + d²)`, in (0, 1] |
  | `inner_product` / `dot` | `1 - a·b` | `(1 + a·b) / 2`; in [0, 1] for unit vectors |

  Neo4j 5 has no inner-product index; that row uses Lucene's `DOT_PRODUCT`
  score, which is the cosine score for unit vectors.

  **What to change.** The rows still come back nearest first, so a query that
  only reads the order needs nothing. A query that reads the number does:

  - `ORDER BY score` (ascending, to put the nearest first) becomes
    `ORDER BY score DESC`, or keep it and yield the old value:
    `YIELD node, distance ... ORDER BY distance`.
  - A threshold such as `WHERE score < 0.2` becomes `WHERE distance < 0.2`, or
    the equivalent similarity (`WHERE score > 0.9` for cosine).
  - Code that stored or compared the yielded number as a distance should yield
    `distance` instead. Its values are exactly what `score` returned before.

  The HTTP `/api/vector-search` response is unchanged: it already returns both
  `distance` and its own `score`.

- **A four-argument `db.index.vector.queryNodes` is read as Neo4j's form only
  when the fourth argument is a map (#1971).** Neo4j 5.18 added an options map
  as the fourth parameter. A call that passed something else fourth was being
  read as that form; it is now rejected rather than silently reinterpreted.
- **`algo.*` configuration maps reject keys the algorithm reads but does not
  accept, and accept keys it ignores.** A misspelled key that happened to be
  read was previously taken; it now fails. A key the algorithm genuinely
  ignores no longer fails.

## Added

### Query and indexing

- **`CREATE` / `SHOW` / `DROP` / `REBUILD STRUCTURE INDEX`**, a structure index
  managed from Cypher. `SHOW STRUCTURE INDEXES` reports its backbone and
  grouping.
- **`PROFILE` reports per-operator memory**, and puts whole details in the
  per-operator section rather than summarising them away (#2078).

### Vector search

- **`vector.knnGraph` and `vector.similarityJoin` procedures** (#1979).
- **A vector index and a query can both set the HNSW parameters**, and a
  snapshot meeting a target index compares the effective parameters rather than
  the requested ones (#1971).
- **SIMD kernels for `f32` vector distances**, and search indexes built in
  parallel.
- **`queryNodes` accepts `$params` and constant expressions** for its vector and
  `k` (#2047).
- **An ann-benchmarks-style recall/QPS harness** for the vector index, plus
  tests against an exact oracle and metamorphic relations.

### Data in and out

- **RDF in and out of `samyama convert`** (#1912): Turtle, N-Triples and RDF/XML
  both ways, JSON-LD out.
- **`samyama-cli load <kg>`** downloads a published knowledge graph, verifies it
  and loads it (#1759).
- **`sdk(python)`: `open_snapshot`, `import_snapshot`, `export_snapshot`** in
  embedded mode.
- **`sdk`: NLQ in embedded mode**, from Rust and Python.
- **A snapshot property audit** that reports empty and low-information columns,
  available as a script.

### Operations

- **`GET /api/algorithms/catalog`** lists every algorithm `CALL algo.*` runs.
- **RESP writes are audited and `INFO` reports real numbers** (#2081).
- **`algo.or.solve` accepts a seed**, so a `CALL` can be reproduced (#2061).
- **Windows support**: snapshot keys, encrypted snapshots and persist all work
  on Windows (#1696).

### Vector functions


- **`vector.similarity.cosine(a, b)` and `vector.similarity.euclidean(a, b)`**,
  Neo4j 5's similarity functions (#1980). They return the same number as the
  index's `score` for the same pair, so a query can filter on either.
- **`vector.distance(a, b, metric)`**, also spelled `vector_distance`, with
  Neo4j's metrics `'EUCLIDEAN'`, `'EUCLIDEAN_SQUARED'`, `'MANHATTAN'`,
  `'COSINE'`, `'DOT'` and `'HAMMING'` (#1980). The metric is a string, not a
  bare word as in Cypher 25.

## Fixed and hardened

### Correctness

- **`algo.scc` uses an iterative Tarjan**, so a large graph can no longer abort
  the server by exhausting the stack (#2043).
- **A strict range excludes its bound after `WITH` or `OPTIONAL MATCH`.** It was
  including it.
- **`SHOW STRUCTURE INDEXES` reports backbone and grouping**, which it omitted.
- **`algo.or.solve` refuses a multi-objective solver without `costProperties`**
  rather than running one that cannot be scored (#2060).
- **`algo.*` catalog rows list every column**, including `mst`'s edge-row
  columns, and every row's columns are checked.
- **List properties survive `/api/import/json`**, and what cannot be stored is
  refused rather than dropped (#2047).
- **Infinities and NaN survive a `.sgsnap` round trip** (#1912).
- **RDF read and write losses found in review are reported** rather than passing
  silently (#1912), an ambiguous language-map key is written as a blank node,
  and the null test's snapshot goes through the mapped RDF writer.
- **`ExportStats.bytes_written` is the bytes written**, not 0.

### Vector search

- **Filtered ANN widening is costed against an exact live scan**, both
  base-layer link sets are accounted for in scan cost, and an exact search is
  used when tombstone over-fetch outweighs a live scan.
- **A `WHERE` on the yielded node is applied inside the vector search**, and a
  `MATCH` expands from the rows of a vector search instead of joining against
  them.
- **Volatile conjuncts stay above the vector search** (#1969).
- **A vector index's resident bytes count the current-entry map.**
- **Operators can raise the query time limit** and finished index builds are
  kept.

### Persistence

- **Every tenant-scoped scan and delete is bounded to its own rows** (#2108).
  `scan_nodes` and `scan_edges` used `prefix_iterator_cf`, which sets
  `prefix_same_as_start` — inert unless the column family has a prefix
  extractor, and none was configured. Both seeked to `{tenant}:` and then ran to
  the end of the column family, deserialising whatever followed as the
  requested tenant's rows. They now carry an explicit upper bound and check each
  key's shape before using it. This was **not a live exposure**: an OSS build
  serves only `default` and refuses any other graph, so no other tenant's rows
  exist to read. What was wrong is that the isolation rested on that refusal
  rather than on the keys — and the module's own documentation claimed the key
  encoding provided it. One configuration did misbehave, which is why the fix is
  worth having: `examples/banking_demo.rs` persists nodes and edges under
  `retail_banking`, `corporate_banking` and `wealth_management`, so a RocksDB
  directory that example produced holds four prefixes. Recovering `default`
  from it read on past its own rows into the two prefixes that sort after
  `default:`.
- **Dropping a graph no longer deletes a differently-named tenant's rows**
  (#2108). `delete_graph` ended its range by incrementing the last byte of
  `{tenant}:{kind}:`, which is only exact while no tenant id contains `:`.
  Dropping `t` spanned `["t:n:", "t:n;")`, and a tenant named `t:n` writes keys
  inside it. The delete now shape-checks each key and batches.
- **`list_persisted_tenants` reports the whole tenant id** (#2108). It split at
  the first `:`, so a tenant named `a:b` was reported as `a`.
- **Dropping a graph also drops its index catalog** (#2108). `delete_graph`
  iterated only `nodes` and `edges`, leaving `catalog:{tenant}` in `indices`.
  Since `GraphStore::clear()` drops the in-memory indexes, that catalog was the
  surviving copy, so a restart after a drop could bring the deleted graph's
  indexes back — the shape of #1110.

### Tooling and scripts

- **The snapshot property audit** rejects malformed records, unknown or missing
  record types, and numbers that overflow to infinity; validates thresholds;
  keeps unlabeled nodes and untyped edges out of real groups; and never reports
  a truncated or unreadable snapshot as clean.

## Security

- **Snapshot import charges every row against the tenant quota and bounds its
  line length.** `/api/snapshot/import` previously had no quota ceiling, did not
  go through the mutate path, and on a default server needed no credential, so a
  snapshot import could write past a tenant's limits. Reported by **kta1kri**;
  thank you. The engine fix is #2031, for the report in #1495.

## Continuous integration

- **macOS ARM64 and Windows are tested before anything reaches `main`**
  (#1696). Tests build Windows-safe paths, and the macOS runner frees disk
  before the build.
- **A pull request starts one workflow rather than three.** The KG catalog check
  and the sort-cost measurement are called from `ci.yml` instead of carrying
  their own `pull_request:` triggers. Neither gates a merge.
- **The Dockerfile's `COPY` sources are checked on every pull request.**
  v1.14.0 shipped with no container image because `cli/` moved and the
  Dockerfile still named it; the pull request that broke it touched no
  Dockerfile line.
- **`publish-crate` can skip an already-published crate.** The branch that was
  supposed to make a partial release re-runnable could never execute.
