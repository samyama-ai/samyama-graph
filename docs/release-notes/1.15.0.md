# Release Notes — v1.15.0

**Unreleased.** Entries are added as changes merge; the date, the commit count
and the summary are written with the version bump.

## Read this before upgrading

- **`db.index.vector.queryNodes` yields `score` as a similarity, higher is
  better (#1980).** It used to be the raw distance, lower is better: the nearest
  neighbour of a query scored about 0. Neo4j's `score` is a similarity in [0, 1],
  so a query ported from Neo4j with `ORDER BY score DESC` or `WHERE score > 0.9`
  returned the worst matches. `score` now follows Neo4j:

  | index metric | `distance` (the old `score`) | `score` |
  |---|---|---|
  | `cosine` | `1 - cos` | `(1 + cos) / 2`, in [0, 1] |
  | `l2` / `euclidean` | Euclidean distance `d` | `1 / (1 + d²)`, in (0, 1] |
  | `inner_product` / `dot` | `1 - a·b` | `(1 + a·b) / 2`; in [0, 1] for unit vectors |

  Neo4j 5 has no inner-product index; that row uses Lucene's `DOT_PRODUCT`
  score, which is the cosine score for unit vectors.

  **What to change.** The rows still come back nearest first, so a query that
  only reads the order needs nothing. A query that reads the number does:

  - `ORDER BY score` (ascending, to put the nearest first) becomes
    `ORDER BY score DESC`, or keep it and yield the old value:
    `YIELD node, distance ... ORDER BY distance`.
  - A threshold such as `WHERE score < 0.2` becomes `WHERE distance < 0.2`, or
    the equivalent similarity (`WHERE score > 0.9` for cosine).
  - Code that stored or compared the yielded number as a distance should yield
    `distance` instead. Its values are exactly what `score` returned before.

  The HTTP `/api/vector-search` response is unchanged: it already returns both
  `distance` and its own `score`.

## Added

- **`vector.similarity.cosine(a, b)` and `vector.similarity.euclidean(a, b)`**,
  Neo4j 5's similarity functions (#1980). They return the same number as the
  index's `score` for the same pair, so a query can filter on either.
- **`vector.distance(a, b, metric)`**, also spelled `vector_distance`, with
  Neo4j's metrics `'EUCLIDEAN'`, `'EUCLIDEAN_SQUARED'`, `'MANHATTAN'`,
  `'COSINE'`, `'DOT'` and `'HAMMING'` (#1980). The metric is a string, not a
  bare word as in Cypher 25.
