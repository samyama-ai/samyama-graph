# Release Notes — v1.16.0

**Date:** 2026-11-16 · **Commits since v1.15.0:** 201 (50 non-merge)

This release makes SPARQL actually execute, adds request correlation and a slow-query
log, brings the NLQ translation cache and structured plan output, extends the
optimization solver set to 35, and ships `samyama-cli pull`. Vector search gains
checkpoint reload, multi-vector and sparse scoring, and a selectivity-driven order for
vector-plus-hierarchy queries. It also pins every CI runner to Ubuntu 24.04, without
which this release could not have been built at all.

## Read this before upgrading

- **SPARQL now returns errors where it used to return nothing (#2100).**
  `SparqlEngine::query` previously returned an empty result for *every* query — the
  parser, executor and optimizer were stubs — and `update()` returned `Ok` while
  writing nothing. An empty answer to a query the engine did not understand is
  indistinguishable from a genuine no-match, so a caller could not tell a miss from a
  missing feature. Both now behave honestly: supported queries evaluate, and anything
  not yet evaluated is **an error naming the feature**. That covers aggregates and
  `GROUP BY`, `BIND`, property paths, `VALUES`, `MINUS`, `GRAPH`, `SERVICE`, string
  functions such as `STRSTARTS`, `CONSTRUCT` and `DESCRIBE`. `update()` returns an
  error.

  **What to change.** Code that treated an empty SPARQL result as "no data" must now
  handle an error for the unsupported subset. Code that called `update()` and ignored
  the result was never writing anything and now finds out.

- **`EmbeddedClient` refuses a graph other than the one it opened (#2139).** Writes
  are classified by AST rather than by string matching, and a statement naming a
  foreign graph is refused instead of being applied to the open one. This is the
  behaviour a single-graph embedded client should always have had, but it does change
  working code: two of our own examples named a graph explicitly and had to be pointed
  at the served graph (#2186). If an embedded caller passes a graph name, it must match
  the graph it opened.

- **`/api/status` reports degraded persistence (#2082).** It used to return the literal
  string `"healthy"` regardless. After a failed persist it now returns
  `"status":"degraded"` with `storage.persistence_degraded: true`. The reason stays in
  the server log, because it can contain paths. A monitor asserting
  `status == "healthy"` will now see the truth, which may be a new alert. OpenAPI is
  updated.

- **A vector-plus-hierarchy query may choose a different order (#445).** The planner
  now picks hierarchy-first or vector-first by selectivity (see Performance below).
  Results are unchanged; the plan is not. `EXPLAIN` shows the choice, and **the H9
  counts in the hierarchy benchmark move**, so a saved hierarchy-benchmark baseline
  needs re-measuring rather than comparing.

- **Correction to the v1.15.0 notes.** Those notes listed
  `vector.similarity.maxSim` / `sparseDot` (#1978) under *Added*, but the commit is not
  an ancestor of the `v1.15.0` tag — it merged to `dev` after the release branched and
  reaches a tag for the first time **here**. If you went looking for those functions in
  1.15.0 and did not find them, that is why. They are in this release.

## Added

### SPARQL (#2100, part 1 of 5)

- **`SELECT` and `ASK` evaluated over the RDF store**, parsed with `spargebra`.
  Supported: triple patterns and joins, `OPTIONAL`, `UNION`, `FILTER` with
  `= != < <= > >= && || ! BOUND sameTerm`, `ORDER BY` (ASC/DESC), `DISTINCT`, `LIMIT`
  and `OFFSET`. Numbers compare by value, so `"30"^^xsd:integer = 30` holds, and a
  blank node in a query acts as an unprojected variable.
- Still to come in #2100: answering from the live `GraphStore` without a copy, the
  `/api/sparql` endpoint and `CALL rdf.sparql(...)`, then `CONSTRUCT`, the OEH
  hierarchy as `rdfs:subClassOf`, and RDF-star. Today the engine is a library API and
  the RDF store is filled through `samyama convert`.

### Observability

- **Request ids correlate every log line with its request (#2076).** Each HTTP request
  and RESP command runs in a `request` span carrying `request_id`, `protocol` and
  `tenant`; HTTP adds `method` and `path`, RESP adds `command`. HTTP returns the id in
  **`X-Request-Id`**, exposed through CORS. A caller's own id is kept when it is 1–128
  characters of letters, digits and `- _ . :`, and replaced rather than refused
  otherwise. Requests refused for a credential (401) still get an id. Streamed NDJSON
  queries carry the span onto the blocking thread, so their lines keep the id.
  Client-supplied names are written to the span only when they cannot forge a text log
  line, and appear as `(unloggable)` when they could. `ops/grafana/README.md`
  documents the fields.
- **`GET /api/slowlog`** keeps the recent slow queries and serves them, newest first.
- **JSON logs** via `--log-format` / `SAMYAMA_LOG_FORMAT`, with structured slow-query
  fields.
- **Result-cache hits and parse errors are counted and exported**, and HTTP audit
  entries carry tenant, `is_write` and a query hash.

### Query and NLQ

- **`EXPLAIN (FORMAT JSON)` and `PROFILE (FORMAT JSON)`** return the plan as a
  structured map rather than text to be parsed.
- **A repeated question is answered from a translation cache** (AI-13, #1743): the
  Cypher already generated is reused, with no second model call and no tokens. This is
  the cache half of AI-13; constrained decoding remains open (#1722).
- **NLQ carries a response schema to the model.**

### Optimization

- **`algo.or.solve` reaches 35 solvers** with **CMA-ES**, **MOEA/D** and **SPEA2**
  (OPT-13), and CMA-ES is reproducible through the seed.
- **`algo.or.constrainedShortestPath`** (OPT-06), the first graph-native template.

### Algorithms and ML

- **The algorithm catalog describes each algorithm's parameters**, and the
  unknown-algorithm error lists every catalogued algorithm instead of only saying no.
- **Negative sampling for link prediction, callable from Cypher** (ML-04).

### Vector search

- **HNSW graphs reload from checkpoints without re-inserting**, and checkpoints are
  published as **atomic checksummed generations**.
- **`vector.similarity.maxSim(query, doc[, metric])` and
  `vector.similarity.sparseDot(a, b)`** (#1978): ColBERT-style MaxSim over
  multi-vectors and the inner product of sparse vectors. Query-time scoring for
  reranking; there is still no multi-vector or sparse index.
- **Filtered exact scans are costed against bounded widening**, and a filtered-recall
  sweep measures across selectivity and correlation.

### CLI

- **`samyama-cli pull <kg>`** (#2003) downloads a published KG and verifies it to a
  file, with the same SHA-256 check as `load`, for a machine with no server yet or a
  KG fetched once and imported repeatedly. It writes `./<kg>.sgsnap` by default (`-o`
  names a file or directory), downloads to a temporary name in the same directory and
  renames only after size and digest match, deletes a failed download, keeps and
  verifies an existing correct file without re-downloading, and **refuses a destination
  holding anything else** — checked again just before the rename. `--format json`
  prints `kg`, `path`, `bytes`, `sha256`, `downloaded` and `seconds`.

### Diagnostics

- **`doctor` checks persistence, memory, metrics, limits and latency (#2082):**
  `persistence` fails when degraded; `server memory` warns at 80% of host RAM, and
  only when the server is local; `metrics` warns when `/metrics` carries no
  `samyama_` metric; `open files` warns under 4096; `nlq config` warns on what the
  server's own validation refuses; `latency` warns when `RETURN 1` p95 exceeds 25 ms
  (DX-09 H2); `resp port` fails when nothing listens. A 401 or 403 is **Skipped**, not
  failed — the client has no credential to send, so it says nothing about the server.

## Fixed and hardened

- **The HNSW walk skips dead entries and reports them**, and deletes no longer force
  an exact scan at 10% (#1972).
- **Checkpoint files are fsynced through a writable handle** — `File::open().sync_all()`
  is `os error 5` on Windows, because `FlushFileBuffers` needs write access — and the
  checkpoint **directory** is fsynced on Unix only, where that is meaningful.
- **`/api/slowlog` takes its id inside the lock**, so newest-first stays in id order.
- **`EmbeddedClient` classifies writes by AST** rather than by inspecting text (#2139).
- **The algorithm catalog lists the parameters added since #2062.**
- **Benchmarks and the nightly sweep report honestly:** a lone `--gt` is an error, both
  sweep stages classify alike, **a non-zero exit outranks a `SKIP:` marker**,
  `ann_benchmark` skips without a dataset instead of failing the nightly, and the
  filtered-ANN bench is skipped rather than run argument-less.

## Performance

- **Vector search combined with a hierarchy subtree filter picks its order by
  selectivity (#445).** A small subtree is scanned and its vectors scored exactly
  (hierarchy-first); a large one runs the vector search and filters its hits
  (vector-first). `EXPLAIN` reports the choice as
  `order=hierarchy-first, subtree=N` or `order=vector-first`.

## Continuous integration

- **Every workflow is pinned to `ubuntu-24.04`.** `ubuntu-latest` began resolving to
  **Ubuntu 26.04**, whose GCC no longer pulls `<cstdint>` in transitively, and RocksDB
  8.10.0 — what `rocksdb = "0.22"` resolves to via `librocksdb-sys 0.16.0+8.10.0` —
  does not include it where it uses the fixed-width types. The build died with 130
  instances of `'uint64_t' has not been declared` before a single test ran. Two things
  disguised it as flakiness: the image rollout is progressive, so the same commit
  passed or failed by which runner it landed on, and `rust-cache` hid it whenever a
  built `librocksdb-sys` was already cached, exposing only cold builds. The ARM legs
  were never affected, having already named `ubuntu-24.04-arm`. Moving past
  `rocksdb = "0.22"` is the real fix for 26.04 and is tracked separately in **#2191**,
  because RocksDB 8.10 → 11.8 crosses eleven minor releases touching on-disk format
  compatibility and the options API, and that needs its own measurement.
- **The conformance gates run beside the test job** instead of after it, taking the ARM
  test leg from about 59 to 37 minutes.
- **The `gak` test locates the demo example** without assuming Cargo's build layout.

## Known at release

Recorded here rather than discovered later:

- **`examples/hier_benchmark.rs` exits 1 on this tree (#2188), and the nightly reports
  the stage green.** `verify-sweep.sh` files a clean `exit(1)` as `NEEDS-INPUT`, and
  the gate counts only `PANIC` and `OOM` (#2187), so the failure passed unnoticed and
  its log was not kept. The example exits 1 from two places: a disagreement between the
  hierarchy index and the unindexed ground truth, or a corpus skip that outlived its
  cause. **Which one fires is not yet established.** The example itself is unchanged in
  this range, and #445's own note says the H9 counts move and want re-measuring, which
  is the likelier explanation — but a disagreement would be a correctness bug and it
  has not been ruled out. `tests/hier_corpus_skips_expire.rs` passed on the same tree.
- **The HNSW recall assertions fail intermittently (#2120).** Recall is bimodal:
  typically about 0.98, with a rare build near 0.70–0.77, and the draw is fresh on
  every process run rather than per build. It is not a defect in any one change and the
  bars should not be lowered. #2146 bumps `hnsw_rs` to 0.3.5, which seeds the layer
  generator with a constant; it is not in this release.
- **CH-REGRESS's envelope reports `fail` while PERF-18 passes.** The suite also carries
  EVAL-12 and COST-10, and both are unmet: there is no held-out manifest, so every
  tracked LDBC number is in-sample, and no envelope records a dollar figure. The
  release gate reads the PERF-18 verdict, which is `pass` with **zero latency
  regressions** on `aws-r6a.4xlarge-spot` against this release's commit.
