# Release Notes — v1.12.0

**Date:** 2026-10-19 · **Commits since v1.11.0:** 164 (64 non-merge)

Where 1.11.0 was the ingest path, 1.12.0 is **the planner telling you what it
will do, and the storage layer doing less work to do it**. `EXPLAIN` carries
estimates, `USING` hints let you choose where a pattern starts, every index kind
answers for its resident bytes, and a statement's writes reach RocksDB as one
batch with one WAL sync rather than one per row. Behind that, six spec gaps
closed and the CI lane was consolidated to a single required check.

## Read this before upgrading

- **A vector search against an index that does not exist is now an error**
  (#1660). It previously returned an empty answer, which is indistinguishable
  from "no neighbours found". Two tests that had pinned the empty answer now pin
  the error. The index contract is written down.
- **A data directory now declares the format that wrote it, and one that cannot
  be read stops the server** (#1657) rather than starting against data it does
  not understand. Persistence is closed before the refusal, so a directory whose
  tenants cannot be recovered does not leave a half-open store.
- **`POINT INDEX` is refused with its reason** (#1668). Every other index kind
  now accepts both DDL spellings, so statements that previously failed on
  spelling alone will work.
- **A security dependency moved:** `rustls` is upgraded to **0.23.46** for
  published advisories. No API change, but anyone vendoring or pinning
  transitively should take the bump.

## Added — planner and observability

- **`EXPLAIN` prints each operator's estimated rows and cost** (#1670). The API
  corpus was re-recorded against the new output.
- **`USING INDEX` and `USING SCAN` choose where a pattern starts and how**
  (#1675).
- **Every index kind reports its resident bytes**, and the vector index counts
  its HNSW graph rather than only its vectors (#1673).
- **A cyclic pattern closes with one join, planned by default** (#1614), and a
  **join key pairs exactly when the engine's `=` does** (#1822). Two patterns
  naming one relationship are no longer stitched into two hops.
- **A later `MATCH` walks from the bound variable at either end of its path**
  (#1613) — previously only one end was considered.

## Added — storage and throughput

- **A statement's row writes reach RocksDB as one write, not one per row**, and
  **the WAL is synced once per commit, not once per row** (#1666).
- **Snapshot export buffers its writes and serializes in parallel: 3.7× faster**
  (#314).
- **A range over an indexed property reads only the range** (#1482).
- **The query cache hands out a shared AST instead of copying it under its lock**
  (#1672).
- **Counting edges does not walk every node** (#1812).
- **A node created with its properties is full-text indexed** (#1673) — it
  previously required a later update.

## Added — imports and operations

- **An import reports the shape of its merges, not just a count** (#1808, via
  #1847).
- **Crash recovery is tested against repeated `SIGKILL`s** and asserted to be a
  prefix of the acknowledged writes (#481). The test checks the `SET`s that were
  acknowledged rather than every third statement.
- **`samyama_arrow` — query results as Arrow tables and pandas frames** (#1097,
  via #1892). This completes #1097: Arrow/Parquet export and `LOAD PARQUET`
  shipped earlier, and the Python SDK helper that the issue called "what
  remains" is the part that lands here.

## CI and repository

- **One required check.** The PR lane is consolidated behind a single `ci-ok`
  aggregator, because a skipped matrix job never reports its name and so could
  never satisfy a required context (#1863, #1864, #1866, #1869, #1871, #1878,
  #1888). 12 workflows became 11.
- **GPML conformance folded into `ci.yml`**, reusing `test`'s release binary
  instead of building the engine twice — about 11 minutes a run (#1871).
- **The code suites are skipped when a PR changes no code** (#1851), and a
  **docs-only PR still runs the docs gate** (#1854) — `CH-DOC-EXEC` parses the
  very `*.md` files the skip filter had allowlisted, so the first filter had a
  hole that the docs-gate job closes.
- **`publish-crate` no longer runs out of disk** (#1845) and **takes a `ref`
  input** so a fixed workflow can publish an older tag (#1846).
- `api/` is renamed **`openapi/`** (#1837); the 17 example helper folders are
  consolidated into `examples/common/` (#1834); stale top-level files and unused
  scripts are removed (#1835, #1838).

## Fixed

- **NLQ now reads the tenant's saved configuration**, which nothing read before
  (#438, via #1891). A tenant could save an NLQ provider and model and have the
  pipeline ignore both; the saved config is now what the request runs against.
- `supply_chain_demo` reports what it actually computed (#1839), and
  `total_time_ms` is pinned by a test to what it measures, with the done event
  reporting the measured solve time (#1798).
- The example inventory and stale test counts in the docs are refreshed (#1840),
  the README is shortened and corrected on what is OSS versus Enterprise
  (#1836), and each AI-16 clause key is mapped to its section (#1738).

## Known limitations at this release

- **crates.io will publish three of five crates.** `samyama` and `samyama-sdk`
  have never existed on the registry, and the publish workflow authenticates
  with GitHub OIDC Trusted Publishing, which crates.io does not permit to
  *create* a crate — only to add versions to one that exists. Both need a
  one-time manual `cargo publish` from an account-scoped token before CI can
  carry them. `samyama-gpu`, `samyama-graph-algorithms` and
  `samyama-optimization` publish normally.
