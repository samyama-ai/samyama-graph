# Release Notes — v1.13.0

**Date:** 2026-10-26 · **Commits since v1.12.0:** 171 (74 non-merge)

This release adds indexed geographic point queries and a loss-reporting offline
converter, while expanding graph imports, snapshots, algorithms and orchestration.
It also updates the Arrow and Parquet stack and fixes published Rust dependency
advisories.

## Read this before upgrading

- **Arrow and Parquet move from 53 to 60.** Rust applications that exchange
  Arrow types with Samyama should align on Arrow 60; Arrow 53 and 60 types are
  distinct Rust types. Zstd support moves to zstd 0.14.3, addressing the
  advisories reported for the previous dependency chain.
- **Graph conversion reports loss explicitly.** `samyama convert` can refuse a
  lossy conversion when `--require-lossless` is selected, and reports skipped or
  unsupported data instead of implying that every source record was preserved.

## Added

- **Point indexes** use an R-tree for indexed geographic and Cartesian point
  predicates. `CREATE POINT INDEX`, `SHOW INDEXES`, and
  `CALL db.index.point.nearest(...)` are supported; index state is persisted and
  carried through snapshots. Geographic nearest-neighbour results are ranked by
  distance on the sphere.
- **Offline graph conversion** is available through the `samyama convert` CLI
  and the `samyama-convert` crate. The format registry supports graph files,
  loss reports, staged writes, and Neo4j `apoc.export.json` input to `.sgsnap`.
- **Snapshot provenance and public codecs** let applications write standalone
  `.sgsnap` files and inspect the source recorded in a snapshot header.
- **Algorithm write-back** stores algorithm results on nodes with
  `writeProperty`.
- **Reference Airflow and Dagster pipelines** demonstrate retry-safe loading
  against a Samyama server and are exercised in CI.
- **FalkorDB migration support** adds a migration guide and a re-measured
  compatibility corpus.
- **Planner estimates improve** with equi-depth histograms for range
  predicates; all-string `ORDER BY` keys use typed string ordering.
- **SDK and API versioning checks** enforce the documented compatibility policy
  against published SDKs.

## Fixed and hardened

- `LOAD CSV ... AS row MERGE` now runs the merge for each input row. `MERGE`
  applies `ON CREATE SET` and `ON MATCH SET` items in written order.
- Tenant-specific NLQ settings are read by HTTP and RESP requests, and disabling
  NLQ for a tenant is respected.
- Converter output paths and reports reject aliases and symlinks that could
  overwrite the source or redirect a report.
- The publish pipeline and Windows Python wheel build were hardened; Tokio and
  other dependencies were updated for published security advisories.
