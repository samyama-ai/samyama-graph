# Release Notes — v1.17.0

**Date:** 2026-11-24 · **Commits since v1.16.0:** 313 (87 non-merge)

This release puts the HTTP API inside its own published contract, finishes the SPARQL
bridge so queries run against the property graph with no second copy, and adds an
in-memory IVF index, in-filter HNSW search, MUVERA multi-vector encoding and a
BM25-plus-vector-plus-graph `db.hybrid.search`. The planner gains `ANALYZE`, plan
forcing and a point-index path for `ORDER BY point.distance LIMIT k`. OpenTelemetry
traces now carry a span per request stage, every response can carry per-query stats,
and 13 algorithms are rebuilt on one shared frontier module. It also ships `.deb` and
`.rpm` packages with a hardened systemd unit.

## Read this before upgrading

- **A query may no longer end with `WITH` (#2358, #2361).** `MATCH (m) WITH m.city AS
  city, count(m) AS n ORDER BY n DESC LIMIT 1` used to run and answer with a column
  `m` — a variable the `WITH` never kept. That is an answer-shaped reply to a statement
  openCypher refuses, and NLQ models write the shape (four times in the #260
  benchmark), so a wrong query looked like a right one. It is now refused with Neo4j's
  message, *Query cannot conclude with WITH*, as a `ClauseConflict`. Nine forms ending
  in `WITH` are refused and twelve that continue — `RETURN`, `SET`, `DELETE`, `MERGE`,
  `CREATE`, `FOREACH`, a later `MATCH` or `UNWIND` — still run. The openCypher TCK is
  unchanged at 3,843 of 3,847. **If a client relied on the old reply, it was reading a
  column the query did not ask for.**
- **Rejection statuses 415 and 422 are now 400, and every error body is JSON (#1723,
  #2150).** axum's extractors refuse a request before the handler runs and answered in
  `text/plain`, so `{}` sent to `/api/query` got a 422 in plain text while a missing
  field in `/api/import/json` got a 400 in JSON. A generated client parses
  `{"error": …}` and so failed on exactly the answer meant to tell it what was wrong.
  One response layer now re-answers any `text/plain` error as `{"error": "<same
  text>"}`, and 415/422 become 400. **413 keeps its status** (a size limit, not a
  malformed request), as does any 5xx; both are JSON now. Success answers, errors
  already in JSON, and `/metrics` are untouched. Per `docs/VERSIONING.md` this is a fix
  rather than a break: the old answer violated the published document.
- **The SDKs no longer retry a timed-out write (#2175, #2337).** A timeout means the
  server may already have applied the request, so with `max_retries = 2` one `CREATE`
  could become three nodes. Connection failures — where nothing was sent — are still
  retried for every request. Timeouts are now retried only for requests that cannot
  write: `query_readonly` / `readOnly: true`, streaming, NLQ, status and schema. A
  timed-out write is sent once and the error returned. Rust gains
  `SamyamaError::Timeout`, Python gains `samyama.RequestTimeoutError` as a subclass of
  `RuntimeError` so existing `except RuntimeError` handlers keep working. In Rust,
  `HttpError` no longer uses `#[from]`; a manual `From` impl keeps `?` working.
- **`SHOW INDEXES` returns two more columns (#1972, #2227).** A vector index now
  reports its dead entries — those still in the HNSW graph that no longer answer for a
  node, because it was deleted or its value replaced. Until now that count was only a
  Prometheus gauge, so an operator could not see how close an index was to its next
  rebuild. The `show_indexes` entry in the API-stability corpus was updated by hand:
  this is an intentional contract change.
- **A filter calling `rand()` or `randomUUID()` no longer runs in parallel (#1747,
  #2144).** Split across threads, rows took the draws in a different order on each run,
  which is incompatible with an export addressable by `(snapshot hash, query, seed)`.
  Such a filter is now single-threaded; everything else still parallelises.
- **SPARQL no longer keeps a duplicate of the store (#2100, #2223).** The bridge reads
  the property graph where it is. The one unit test that read the second copy now
  checks the same property with `ASK { ?s ?p ?o }`.

## Added

### SPARQL (#2100, part 2 of 5)

- SPARQL evaluates **over the property graph in place**, with no copy of the store.

### API and SDKs

- **Every documented operation answers inside `openapi/openapi.yaml`** (#1723, #2150),
  with a shared `components/responses/BadRequest` referenced by the ten operations that
  read a body or query string but did not list a 400.
- **Rust embedded mode** (#1734, #2295), checked as a user program with no server and
  no socket.
- **Cancellation and pooling in the Python SDK, a connection limit in TypeScript**
  (#1741, #2157). A cancelled `query_stream` raises on the next row and the server sees
  the connection close; a real `SIGINT` reaches Python's handler while the call is
  blocked.
- **`snapshot_hash` on query results, on request** (#1706, #2313), completing the
  engine side of the provenance trio beside `engine_version` and `plan_hash`.

### Query, planner and catalog

- **`ANALYZE :Label`**, and `EXPLAIN` now names the `USING` hints it applied (#2253,
  #2321).
- **Plan forcing** (#2252, #2323): `EXPLAIN (plan=N)`, `plan` and `planner` body
  fields, and a forceable-plan count.
- **`ORDER BY point.distance LIMIT k` reads the point index** (#2255, #2324); the stale
  `POINT INDEX` documentation is corrected.
- **`ANY` and `ANY SHORTEST` answer over an unbounded `WALK`** (#1648, #2352).
- **`memory_bytes` on every plan JSON node**, and why each candidate plan was not run
  (#2013, #2294).
- **A description per algorithm and the bounds the engine enforces** in the catalog
  (#2013, #2314).

### Vector search

- **In-memory IVF index, `kind: 'ivf'`** (#1975, #2286).
- **In-filter HNSW search**, with the predicate inside the walk (#1999, #2331). The
  shared `FilterPlan::decide` makes a three-way exact / in-filter / widen choice; IVF
  prices the walk at infinity since it has none.
- **`vector.muvera.encode`** for multi-vector retrieval (#1978, #2332).
- **`db.hybrid.search`** — BM25 plus vector plus local graph expansion (#1279, #2333).
- **Each vector is held once, in the HNSW graph** (#1973, #2330). An IVF index, which
  has no graph, keeps its one copy beside its lists; `vector_bytes()` counts one copy
  for both kinds.
- **Large exact vector scans score on the GPU** under `--features gpu` (#1977, #2170).
- **`PROFILE` reports the work a vector strategy did** (#1970, #2229).

### Observability

- **OpenTelemetry traces with a span per request stage** (#2077, #2177), plus plan
  estimates and a plan hash on the plan span, a span per model call, and entities on
  the persist span (#2293).
- **Per-query stats on every response, and `GRAPH.SLOWLOG` over RESP** (#2079, #2196).
- **Process RSS, queries in flight, active connections and persistence health** as
  metrics (#2080, #2159).

### Algorithms, ML and agents

- **One shared frontier/traversal module, with 13 algorithms built on it** (#1695,
  #2302).
- **Stream mode and Vector storage for `fastRP` and `node2vec`** (#1736, #2124).
- **Three selectable constraint-handling strategies for the solvers** (#2266, #2328).
- **Leakage-safe splits and a leakage check, callable from Cypher** (#1730, #2142).
- **Exports addressable by `(snapshot hash, query, seed)`, with a manifest** (#1747,
  #2144).
- **Declarative feature definitions with point-in-time materialization** (#1742,
  #2214).
- **A signature contract and repair runner** (#2130, #2222), integrated into its
  callers (#2231), and a graph-native decision-trace core (#2237).

### Packaging and diagnostics

- **`.deb` and `.rpm` (amd64 and arm64) with a hardened systemd unit** attach to every
  `v*` Release and pass cold-container systemd smoke tests; the release binary targets
  glibc 2.34+ (#2203, #2300).
- **`samyama doctor` checks the NLQ provider's endpoint accepts a connection** (#2082,
  #2212), and adds Snap removable-media and data-location checks (#2203, #2299).

## Fixed and hardened

- **Plan-executor telemetry is persisted through the query write path** (#2241, #2322).
  `PlanExecutor::write_telemetry` wrote `(:Question)-[:USED_TOOL]->(:Tool)` straight
  into `GraphStore` with nothing calling `PersistenceManager::apply_mutations`
  afterwards, so the telemetry was either lost on restart or — because the write log
  stays on — saved by the next unrelated write, **under that write's tenant**.
  `agent::memory::record_decision` had the same gap.
- **The Gemini adapter no longer silently weakens a structured-output contract**
  (#2319): a schema that loses constraints is rejected.
- **`PROFILE (FORMAT JSON)` on the clause pipeline is a profile, not an explain**
  (#2156, follow-up to #2059).
- **A query may not end with `WITH`** (#2358, #2361) — see *Read this before
  upgrading*.
- **Snap path checks are Windows-safe** (#2354). Two `doctor` tests asserted Unix
  paths and failed on `windows-2022`.
- **The Ubuntu systemd smoke test resolves `systemctl`** (#2365).
- **A snapshot written by each earlier release still loads the same graph** (KG-11,
  #1794, #2158): `tests/fixtures/snapshots-by-release/` carries one snapshot per
  release from v1.10.0 to v1.14.0 and CI reads each one, cross-architecture on the
  aarch64 job.
- **The README's Cypher examples run, not only parse** (DX-04, #1779, #2197).

## Dependencies

- **`url` 2.5.8 → 2.5.9 for RUSTSEC-2026-0592**, with `form_urlencoded` 1.2.3 as
  required (#2342).
- **`parquet` 60.0.0 → 60.2.0 for RUSTSEC-2026-0595** — an unsoundness in Apache Arrow
  Rust where the header and bitsets of a Bloom filter were written in plaintext when
  writing an encrypted Parquet file. Patched versions refuse to write Bloom filters
  when encryption is enabled. The bump carries `arrow-array`, `arrow-buffer`,
  `arrow-cmp`, `arrow-data`, `arrow-ipc`, `arrow-schema` and `arrow-select` to 60.2.0.
  **Files already written with encryption and Bloom filters stay affected** and should
  be rewritten with Bloom filters disabled.
- **The `chrono` and `chrono-tz` unmaintained advisories are ignored with a recorded
  reason** (#2291). Every version is affected, there is no successor release, and
  neither is a vulnerability: `chrono` arrives transitively through arrow 60, and
  `chrono-tz` resolves IANA zones for temporal Cypher, so replacing it is a migration
  rather than a bump.

## Benchmarks

- Resource and cost profile per quantization (#1989, #2168); graph-reachability
  predicates in the filtered sweep (#1985, #2228); a graph-plus-vector hybrid
  benchmark with GraphRAG-shaped queries (#1987, #2320); a streaming-churn benchmark

## Known at release

Recorded here rather than discovered later:

- **The HNSW recall assertions still fail intermittently (#2120).** Recall is bimodal:
  typically about 0.98, with a rare build near 0.70–0.77. #2146 shipped in v1.16.0 and
  made a given input build the same graph, which makes the dip reproducible for a fixed
  input rather than explaining it. **What makes a rare build lose a quarter of its
  neighbours is still unknown**, and the bars should not be lowered.
- **`examples/hier_benchmark.rs` exits 1 (#2188) and remains undiagnosed.** The example
  is unchanged in this range. #445's note says the H9 counts move and want
  re-measuring, which is the likelier and benign explanation, but a disagreement
  between the hierarchy index and the unindexed ground truth would be a correctness
  bug and has not been ruled out.
- **Four crates are stranded at 1.14.0 on crates.io.** `publish-crate` has failed on
  every tag from v1.12.0 with `403 Forbidden: The provided access token is not valid
  for crate 'samyama'`. `samyama-gpu`, `samyama-graph-algorithms` and
  `samyama-optimization` publish; **`samyama`, `samyama-sdk`, `samyama-cli` and
  `samyama-convert` do not**, and this is the third release they have missed. The fix
  is owner-side — a crates.io Trusted Publishing entry or a token scoped to those four
  names — after which `publish-crate` can be re-dispatched on the tag, since it skips
  crates already published.
- **CH-REGRESS's envelope reports `fail` while PERF-18 passes.** The suite also carries
  EVAL-12 and COST-10, and both remain unmet: there is no held-out manifest, so every
  tracked LDBC number is in-sample, and no envelope records a dollar figure. The
  release gate reads the PERF-18 verdict.
